    01. Utilizando a Linha de Comando

    Explique o que é a linha de comando e cite pelo menos cinco comandos que podem ser utilizados no Windows ou Linux, explicando para que serve cada um.

    A linha de comando, ou conhecido como: terminal / prompt de comando é uma interface de texto onde o usuário digita instruções diretamente para o sistema operacional executar, sem precisar clicar em ícones ou janelas.     02_validacao_de_links.md

    02. Validação de Links em Aplicações

    O que significa validar um link em uma aplicação? Explique por que essa validação é importante para a segurança e para a experiência do usuário.

    Validar um link significa conferir, antes de usá-lo, se ele tem um formato correto de URL e se aponta para um destino real, seguro e esperado — e não para um endereço malicioso, quebrado ou falso.

    Segurança

    Sem validação, um sistema pode redirecionar o usuário para sites de phishing, permitir ataques de injeção de código (como XSS) ou abrir links que executam scripts maliciosos escondidos em parâmetros da URL.

    Experiência do usuário

    Links quebrados (erro 404), redirecionamentos incorretos ou botões que não levam a lugar nenhum frustram o usuário e passam uma sensação de descuido com o sistema. Validar evita esse tipo de falha antes que ela chegue até quem está usando a aplicação.

    03_paradigma_poo.md

    03. Entendendo o Paradigma de Orientação a Objetos

    Explique com suas palavras o que é POO e cite duas vantagens desse paradigma em relação ao paradigma procedural.

    Programação Orientada a Objetos é uma forma de organizar o código em que a gente representa partes do sistema como "objetos": pacotes que juntam dados (atributos) e ações (métodos) relacionados a uma mesma entidade do mundo real ou do problema que está sendo resolvido — por exemplo, um objeto Cliente ou um objeto Pedido.

    Duas vantagens sobre o paradigma procedural

    1. Reaproveitamento de código: com herança, uma classe pode reutilizar o comportamento de outra sem reescrever tudo do zero.
    2. Organização e manutenção mais fáceis: cada objeto cuida dos seus próprios dados, então mudanças em uma parte do sistema tendem a afetar menos outras partes, o que facilita corrigir e evoluir sistemas grandes.
    04_funcoes.java

    04. Funções e Protótipos em Programação

    O que é uma função? Explique sua importância e apresente um exemplo simples.

    Uma função é um bloco de código nomeado que executa uma tarefa específica, podendo receber valores de entrada (parâmetros) e devolver um resultado (retorno). Em vez de repetir a mesma lógica várias vezes no programa, a função permite chamar esse bloco sempre que ele for necessário.

    Sua importância está em três pontos principais: evita repetição de código, organiza a lógica em partes menores e mais fáceis de entender, e facilita a manutenção — se algo precisa mudar, muda-se em um único lugar.

    Somar.javajava
    public static int somar(int a, int b) {
    // recebe dois números e devolve a soma
    return a + b;
}
    05_classes_heranca.java

    05. Classes e Herança

    O que é uma classe? O que é um objeto? O que é herança? Dê um exemplo utilizando animais, veículos ou pessoas.

    • Classe: é o molde/modelo que define quais atributos e métodos os objetos daquele tipo vão ter.
    • Objeto: é uma instância concreta de uma classe — a classe é a "planta baixa", o objeto é a "casa construída" a partir dela.
    • Herança: mecanismo em que uma classe (filha) reaproveita atributos e métodos de outra classe (mãe), podendo ainda adicionar ou modificar comportamentos próprios.
    📷 Coloque aqui a imagem ilustrativa (ex.: cachorro e gato)
    imagens/animais-heranca.jpg
    Animal.javajava
    public class Animal {
    protected String nome;

    public void emitirSom() {
        System.out.println("Som genérico de animal");
    }
}

public class Cachorro extends Animal {
    public void emitirSom() {
        System.out.println("Au au!");
    }
}

public class Gato extends Animal {
    public void emitirSom() {
        System.out.println("Miau!");
    }
}

    Aqui, Cachorro e Gato herdam o atributo nome de Animal, mas cada um redefine o comportamento de emitirSom().

    06_encapsulamento.md

    06. Encapsulamento

    Explique o conceito de encapsulamento e por que ele é importante no desenvolvimento de sistemas.

    Encapsulamento é o princípio de esconder os detalhes internos de uma classe e controlar o acesso a eles, geralmente deixando os atributos como private e liberando o acesso só por meio de métodos públicos (os famosos getters e setters).

    Ele é importante porque protege os dados contra alterações indevidas (por exemplo, impedir que a idade de uma pessoa receba um valor negativo), permite mudar a implementação interna de uma classe sem quebrar o restante do sistema, e deixa claro qual é a "porta de entrada" oficial para mexer em cada informação.

    07_polimorfismo.java

    07. Polimorfismo

    Explique o que é polimorfismo e apresente um exemplo simples.

    Polimorfismo é a capacidade de objetos de classes diferentes responderem de formas diferentes a uma mesma chamada de método, cada um "do seu jeito", mesmo compartilhando a mesma classe pai ou interface.

    Polimorfismo.javajava
    Animal[] bicho = { new Cachorro(), new Gato() };

for (Animal a : bicho) {
    a.emitirSom(); // chama o método certo para cada tipo
}
// Saída:
// Au au!
// Miau!

    O código chama emitirSom() sem se preocupar se o objeto é um cachorro ou um gato — cada um executa a sua própria versão do método.

    08_solid.md

    08. Princípios SOLID

    Pesquise e explique, resumidamente, cada um dos cinco princípios SOLID.

    SSingle Responsibility Principle — cada classe deve ter uma única responsabilidade, ou seja, um único motivo para mudar.
    OOpen/Closed Principle — as classes devem estar abertas para extensão, mas fechadas para modificação; adiciona-se comportamento novo sem alterar o código existente.
    LLiskov Substitution Principle — uma classe filha deve poder substituir a classe mãe em qualquer parte do sistema sem quebrar o funcionamento.
    IInterface Segregation Principle — é melhor ter várias interfaces pequenas e específicas do que uma única interface grande e genérica que obriga classes a implementar métodos que não usam.
    DDependency Inversion Principle — o código deve depender de abstrações (interfaces) e não de implementações concretas, facilitando trocar uma peça do sistema sem afetar as outras.

    13_paradigma_procedural.md

    13. Paradigma Procedural

    O que é programação procedural? Quais suas vantagens e limitações?

    Programação procedural é o paradigma em que o código é organizado como uma sequência de instruções e funções (procedimentos) que são executadas em ordem, sem o conceito de objetos combinando dados e comportamento.

    Vantagens

    • Mais simples de entender para programas pequenos e lineares.
    • Menor overhead de execução, já que não há a estrutura extra de classes e objetos.

    Limitações

    • Fica difícil de manter conforme o sistema cresce, pois dados e funções ficam soltos, sem organização em torno de entidades.
    • Menor reaproveitamento de código comparado à herança e ao polimorfismo da POO.
    14_pilares_poo.md

    14. Introdução à Orientação a Objetos

    Pesquise e explique os quatro pilares da POO.

    • Abstração: focar apenas nas características essenciais de um objeto, escondendo detalhes de implementação que não são relevantes para quem está usando a classe.
    • Encapsulamento: proteger os dados internos de um objeto, controlando o acesso por meio de métodos públicos.
    • Herança: permitir que uma classe reaproveite atributos e métodos de outra classe já existente.
    • Polimorfismo: permitir que um mesmo método se comporte de forma diferente dependendo do objeto que o executa.
    15_aluno.java

    15. Comportamentos dos Objetos

    Diferença entre atributo e método. Crie uma classe Aluno com pelo menos 5 atributos e 5 métodos.

    Atributo é uma característica ou dado do objeto (o "estado" dele), enquanto método é uma ação ou comportamento que o objeto pode executar (o "verbo" dele).

    Aluno.javajava
    public class Aluno {
    // atributos
    private String nome;
    private int matricula;
    private int idade;
    private String curso;
    private double[] notas;

    // métodos
    public void matricular(String curso) {
        this.curso = curso;
    }

    public double calcularMedia() {
        double soma = 0;
        for (double n : notas) soma += n;
        return soma / notas.length;
    }

    public boolean verificarAprovacao() {
        return calcularMedia() >= 6.0;
    }

    public void exibirDados() {
        System.out.println(nome + " - " + curso);
    }

    public void alterarCurso(String novoCurso) {
        this.curso = novoCurso;
    }
}
    16_composicao.java

    16. Composição de Objetos

    Explique o que é composição de objetos. Dê um exemplo com Carro e Motor.

    Composição é uma relação do tipo "tem-um", em que uma classe é formada por outra classe como parte da sua estrutura — diferente da herança, que é uma relação "é-um". Aqui, um Carro não é um Motor, mas ele possui um Motor.

    Carro.javajava
    public class Motor {
    private int potenciaCavalos;

    public void ligar() {
        System.out.println("Motor ligado");
    }
}

public class Carro {
    private Motor motor; // composição: Carro "tem um" Motor

    public Carro() {
        this.motor = new Motor();
    }

    public void ligarCarro() {
        motor.ligar();
    }
}

    18_reflexao.md

    18. Questão de Reflexão

    Você acredita que aprender POO é importante para quem deseja trabalhar como desenvolvedor? Justifique.

    Sim. A grande maioria das linguagens e frameworks usados no mercado hoje — Java, C#, Python, PHP, entre outras — é baseada total ou parcialmente em Orientação a Objetos. Entender esse paradigma não serve só para escrever código em Java, mas dá uma base de raciocínio (organizar o problema em entidades, responsabilidades e comportamentos) que se aplica a praticamente qualquer linguagem moderna. Além disso, sistemas profissionais tendem a ser grandes e mantidos por várias pessoas ao longo do tempo, e os conceitos de POO — como encapsulamento e reaproveitamento por herança — são justamente o que torna esse tipo de manutenção viável em equipe.
